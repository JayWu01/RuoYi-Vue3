## 追加：后端 getRankList 报 invalid comparison 诊断（本轮只诊断，未改任何后端代码）

用户反馈 `/policeScreen/getRankList` 报 `invalid comparison: java.util.Date and java.lang.String`。

根因：`PoliceScreenStatisticsMapper.xml` 的 `selectRankByType`（行 279/282/294/297/309/312/324/327，共 8 处）把 `<if>` 写成
`test="query.startDate != null and query.startDate != ''"`，而 `PoliceStatQueryDTO.startDate/endDate` 是 `java.util.Date`。
OGNL 比较 Date 与 String 字面量时抛 `IllegalArgumentException: invalid comparison`，被 MyBatis 包成 `BuilderException: Error evaluating expression`。
证据：同文件既有的 `AlarmwhereCondition`（行 8-13）与 `HitwhereCondition`（行 23-28）只判 `!= null`，写法正确 —— 说明新写的 SQL 没照抄既有风格。

修复方案（精确到行，等用户确认后应用）：8 处删掉 `and query.startDate != ''` / `and query.endDate != ''`，只留 `!= null`。

顺带发现（均未改动，待用户确认）：
- `PoliceStatQueryDTO` 行 45 用户已自行补上 `rankType` ✓（上轮我撤销的字段，用户自己加了）。
- 时间格式隐患：DTO 标注 `@JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss")`，而前端 `toMonthDateRange()` 在选了月份时传 `yyyy-MM-dd`（如 `2026-01-01`），Jackson 用该 pattern 解析会失败。建议前端补成 `-01 00:00:00` 与 `-末日 23:59:59`。
- `selectRankByType` 行 306 `SUM(sc.unwarnedMinor)` 用驼峰列名，而同段其他列是下划线风格（`net_fugitive_count`、`open_door_count`），需确认真实列名。
- 该 SQL 全程未使用 `deptId`/`deptName` 过滤，排名面板的单位筛选不生效。
- `StrikeCurrentReportMapper.xml` 行 21/24 也写了 `!= ''`，但其 DTO 字段是 `String`，不受影响。
