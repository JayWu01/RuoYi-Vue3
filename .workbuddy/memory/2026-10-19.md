## 重构：接处警报表改为「SQL 只分组统计 + Java 组装部门结构」（用户提出 join 效率低）

动机：原 XML 里 `police_alarm_record` INNER JOIN sys_dept 两次（警务站+大队），用户认为低效，要求 SQL 先按分组统计好，再在 Java 里查部门、按 deptId 一一匹配成报表模板。

改动（全部在本次新增的报表文件内，未碰其他代码）：
- 新增 `vo/reportVo/alarm/AlarmReportStatVO.java`（disposeUnitId + 4 项统计，纯聚合结果载体）
- 新增 `vo/reportVo/alarm/AlarmDeptVO.java`（deptId/deptName/parentId/orderNum）
- `AlarmReportMapper.java`：改为 `selectAlarmStats(query)` + `selectDeptList()`
- `AlarmReportMapper.xml`：
  - `selectAlarmStats` 只查 police_alarm_record 单表，GROUP BY dispose_unit_id（无 join），且 `dispose_unit_id IS NOT NULL`
  - 时间条件改为可走索引写法：`alarm_time >= #{startDate}` / `alarm_time < DATE_ADD(#{endDate}, INTERVAL 1 DAY)`，**不用 DATE(alarm_time)**（否则索引失效）
  - `selectDeptList`：`SELECT dept_id, dept_name, parent_id, order_num FROM sys_dept WHERE del_flag='0'`
- `AlarmReportServiceImpl` 重写：statMap(deptId→统计) + deptMap + childrenMap；从 parentId(默认101) 递归收集叶子（警务站），按 大队orderNum → 站orderNum → deptId 排序；按 deptId 匹配统计值，**无数据的警务站补 0**；detDailyAvg 仍按大队总/站数/天数；根节点无子部门时返回空列表
- `AlarmReportController.list`：去掉 `startPage()`（PageHelper 无法作用于 Java 组装结果），改为内存分页 `new TableDataInfo(subList, allRows.size())` + code/msg

注意：Java 侧组装后分页必须内存分页，若以后改回 DB 分页需同步调整；报表范围由 parentId=101 的部门树决定，不再由警情数据决定。
验证：mvn compile exit 0，XML 解析通过。
